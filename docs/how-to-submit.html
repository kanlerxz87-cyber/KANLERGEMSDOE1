1. Root Cause & Prevention of "Predicted values must be in range [0, 1]" (IR-PORTAL-05)

Inspecting the official DrivenData reference solution (unet-mc-cv-reference-solution.ipynb, Cells 16 & 19) reveals why GeoTIFFs with outside-footprint NaNs or uncleaned feature nodata fail portal validation:

  1. IEEE-754 NaN Failure on Array-Wide Range Checks: In NumPy, (np.nan >= 0.0) & (np.nan <= 1.0) evaluates to False. The official reference notebook initializes y_out = np.zeros((H, W), dtype=np.float32), applies torch.nan_to_num(...) to input patches, writes predictions in [0.0, 1.0] via sigmoid inside valid cells, leaves outside-footprint cells at 0.0, and writes GTiff with nodata=None.
  2. -3.4028235e+38 Float32 Sentinel Leakage: Raw bands in training_features.tif contain -3.4028235e+38 nodata sentinels; linear combinations or unclipped logits can propagate negative or >1.0 values into footprint pixels.
  3. Multi-Band or Wrong CRS/Transform Exports: Exporting RGBA visualization rasters or reprojected EPSG:4326 rasters fails grid matching against sample_submission.tif (EPSG:32611, 3730 × 3292).
