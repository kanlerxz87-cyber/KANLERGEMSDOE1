Once a candidate has actually been cleared

Confirm the current official outside-footprint/nodata requirement; the local mirror and reference notebook do not establish portal acceptance.
  3. On the New submission page, choose the selected file. Paste the unique note from that file's run card (at most 140 characters), then submit only if all gates still pass. Record the displayed receipt and score with the exact hash; no score is organizer-confirmed without that receipt.

Investigating the reported range error

The exact cause is unknown without the rejected file and portal receipt. Out-of-range values, infinity, nodata sentinels and NaNs in scored pixels are possible causes, not diagnoses. Run the shared scripts/submission_writer.py checks on a candidate and compare its footprint and metadata with an authenticated template. Do not assume that replacing nodata with zeros is accepted: the reference solution is an example, not the portal validator. Local checks cannot guarantee an upload succeeds.

Until the format, uniqueness and selector gates are resolved, do not submit any historical research TIFF. Read the review and limitations.
